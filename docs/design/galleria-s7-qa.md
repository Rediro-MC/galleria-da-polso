## 2. Contratti

### 2.1 `src/c/gal_log.h` — livelli di log (compito C)

```c
/* gal_log.h — log di produzione vs diagnostica (regola 11). Header puro. */
#include <pebble.h>
#ifdef GALLERIA_LOG_VERBOSE
#define LOGV(fmt, ...) APP_LOG(APP_LOG_LEVEL_INFO, fmt, ##__VA_ARGS__)   /* diagnostica del gate: chunk, risorse, strip */
#else
#define LOGV(fmt, ...) ((void)0)
#endif
#ifdef GALLERIA_DEBUG_HEAP
#define LOGH(phase) APP_LOG(APP_LOG_LEVEL_INFO, "heap %s: used=%u free=%u", (phase), (unsigned)heap_bytes_used(), (unsigned)heap_bytes_free())
#else
#define LOGH(phase) ((void)0)
#endif
```
(`##__VA_ARGS__` è già usato dallo stesso `APP_LOG` dell'SDK.) Build: `GALLERIA_DEFINES="GALLERIA_LOG_VERBOSE=1 GALLERIA_DEBUG_HEAP=1 GALLERIA_DEBUG_TIMING=1" pebble build`.

**Restano `APP_LOG` di produzione** (una riga per fase/evento, tutte ≤ 80 caratteri di formato — il firmware tronca a ~100 caratteri con il prefisso `file:riga`): `heap main/init/window_load/deinit` + `heap after first render` (regola 11); `storage: quota=… album=… schema=… manifest=… valid=…` (init); `settings: persist|defaults …` (init); `ui_time: …` (init, accorciata); `sync: open(…)` (init); `sync: msg=… -> act=… out=… code=… off=… st=… heap …` (un rigo per messaggio di controllo, **non** per `PHOTO_DATA`); `sync: end slot=… code=… msgs=… commit … photo … chunk max/avg … heap …` (una per foto, §2.5); `photo: slot %u persist crc %s %u ch %d ms heap …` (una per caricamento: serve a S8); `rot(%s): …` (una per cambio foto); `luma(%s): …` (una per decisione, accorciata a ≤ 80: p.es. `luma(%s): m=%u b=%d+%d h=%d ph=%d w=%d bad=%u(%u/%u) mean=%u fg=%02x halo=%d`); tutti gli `ERROR`/`WARNING` esistenti (accorciati dove serve; il tripwire `sync: dict_write -> %d, msg %u incompleto` **conserva la parola `incompleto`** e il livello WARNING: il test host lo cerca).

**Passano a `LOGV`**: `sync: data slot=… off=… n=… -> act=… code=… %d ms` (per chunk); `sync: inbox_max=… inbox=… chunk=…` (per JS_READY); `digits: font=… size=… … heap …` (per strip caricata); `photo: bitmap …` (init); `photo: resource %u loaded=…` (per demo caricata); `storage: settings written -> %d`; `bt: connected=%d`; `settings: debug save …` (già solo debug). `seed: …` resta sotto `GALLERIA_DEBUG_SEED` com'è.

**`LOGH`** (solo `GALLERIA_DEBUG_HEAP`): `LOGH("services")` in `main.c` dopo le sottoscrizioni ai servizi e `LOGH("unsub")` in deinit dopo le disiscrizioni (sonda dei ~2 KB residui, §7 S4); `LOGH("qv")` in fondo a `ui_time_unobstructed_changed`; `LOGH("shake")` in `model_shake` dopo `prv_apply`; `LOGH("sync_end")` a fine `prv_album_flush` quando la sync torna a riposo.

### 2.2 Strip A a richiesta nel layout B (compito C, `ui_time.c`; `ui_digits.c` invariato salvo §2.6)

Oggi `prv_load_strips()` nel layout B carica **sempre** A + B (A per la riga singola sotto Quick View, S3: "nessuna allocazione a ogni peek"). Nuova regola (D16):
- `need_b = (layout == B)`; font di B = `st->font` se sprite, altrimenti `GAL_FONT_ANTON` (come oggi).
- `need_a = (layout == A && font sprite) || (layout == B && B caricata && obstructed)` dove `obstructed = s_unob_h < s_lay.full.size.h`; font di A nel layout B = **lo stesso font di B**.
- `prv_load_strips()` carica/scarica secondo `need_a`/`need_b` (no-op se già nello stato giusto: `ui_digits_load` ritorna subito con lo stesso font). `prv_refresh_mode()` chiama `prv_load_strips()` **prima** di `prv_pick_mode()`; `ui_time_unobstructed_changed()` aggiorna `s_unob_h` e poi `prv_refresh_mode()` (come oggi). Allocazioni quindi solo in `window_load`, in `ui_time_layout_changed` (impostazioni dal telefono) e nel `did_change` dell'area non ostruita: **mai in `update_proc`** (regola 3).
- Fallimento del caricamento di A sotto Quick View (heap) → `MODE_A_LECO` (fallback già esistente in `prv_pick_mode`). Quick View che finisce → A scaricata (−8.152 B) al `did_change`.
- Costo: una `gbitmap_create_with_resource` (≈ 7,5 KB dalla flash) per ogni peek della timeline nel layout B: evento raro, fuori dal tick. Frammentazione: il blocco A viene allocato/liberato in cima all'heap con la foto e la strip B ferme sotto → nessun buco permanente (da verificare nel gate: 20 cicli QV on/off con heap identico).
- Commenti da aggiornare: intestazione di `ui_digits.h` ("Due taglie possono essere caricate insieme…"), `prv_load_strips`, `ui_time.h` (`ui_time_unobstructed_changed`).

### 2.8 `album.js` — F12 (compito A)

Oggi `plan()` chiama `hasPayload(k, fmt)` = `getItem` dell'intero payload (45,6 KB) per ogni foto e `applyPayload` lo ripete (riga ~355); `load()` lo rilegge. Contratto nuovo:
- Metadato `p.fmts[fmt].stored: true|false` — `true` quando `setPayload` ha avuto successo (in `applyPayload`, nel `loader` di `load()`), `false` per le voci "solo metadati" (dev `url`), rimosso insieme al formato. Il JSON dell'album è la sola fonte per `plan()`: **nessun `getItem` sulle chiavi `galleria.v1.p<slot>.<fmt>` dentro `plan()`, `summary()`, `state()`, `applyPayload()`** (in `applyPayload` la riga "stessi metadati, payload mancante: lo aggiungo" usa `!cur.fmts[fmt].stored`).
- `plan()`: foto candidata se `stored === true` **oppure** c'è un `loader` (dev); altrimenti log "assente e nessun loader: saltata" come oggi.
- `load(cb)`: `getPayload` → se `null` e `stored === true` e nessun loader ⇒ `_dropCorrupt(slot, fmt, 'payload assente')` (rimuove i metadati del formato: il prossimo HELLO **non** la ripianifica → nessun ciclo di retry) e `cb('payload assente')`; con il loader ⇒ percorso attuale e, dopo `setPayload` riuscito, `stored = true` + `_save()`.
- Migrazione: album già salvati senza `stored` → alla lettura (`_load`/normalizzazione) i formati senza il campo ricevono `stored = hasPayload(slot, fmt)` (una sonda per formato, **una sola volta**) e l'album viene riscritto; `v` resta 1.
